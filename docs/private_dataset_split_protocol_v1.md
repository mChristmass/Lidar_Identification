# 私有数据论文划分协议 v1

冻结日期：2026-09-22。

## 1. 目的

本协议将现有1390帧私有数据划分为训练、开发验证和最终确认集合。划分的最小单位是原始采集文件夹；同一采集文件夹的帧不得跨集合。划分只使用来源信息和标签类别计数，不使用任何模型结果。

现有`group_folds`按类别内周期桶拆分连续帧，仅作为历史探索轨道，不再作为论文采集组隔离证据。

## 2. 来源审计结论

- 帧391–1390可以由`second0612/frame_mapping.csv`追溯到14个原始采集文件夹，记为已验证来源。
- 帧1–390的项目内映射只保留`first`批次和连续帧号。使用Depth与Intensity双重内容指纹检索现存原始生成目录后，仅24帧得到唯一匹配，不能据此安全恢复其余帧的采集序列。
- 因此前390帧整体视为一个不可拆的历史组，仅允许进入训练集，不进入开发集或最终确认集。
- 当前标签审计发现帧633和981已经是空标签，但旧类别表仍记为normal。冻结元数据同时保留旧类别，并按当前标签将两帧的有效类别修正为background；二者均位于训练集，不改变集合归属。

## 3. 固定划分

### 开发验证采集文件夹

- `depth_20260129_191730_8000frames`
- `depth_20260129_194946_2000frames`
- `depth_20260129_204454_2000frames`

### 最终确认采集文件夹

- `depth_20260129_195709_8000frames`
- `depth_20260129_195059_2000frames`
- `depth_20260129_200632_10000frames`

其余8个已验证采集文件夹以及不可拆的`first`历史组进入训练集。

生成后的规模为：

| 集合 | 帧数 | 采集组数 | 已验证来源帧数 |
|---|---:|---:|---:|
| train | 970 | 9（含1个未解析历史组） | 580 |
| dev | 137 | 3 | 137 |
| final_test | 283 | 3 | 283 |

`verified_train_indices.*`额外给出不含前390帧的580帧纯已验证训练子集，用于敏感性分析。

## 4. 使用纪律

1. 结构、损失、预处理、训练预算和阈值只能根据训练集及开发集确定。
2. `final_test`不得用于筛选模块、挑选随机种子或调整超参数。
3. 最终确认前必须冻结代码版本、配置、随机种子和checkpoint选择规则。
4. 若最终确认不理想，不得根据`final_test`结果继续修改方法后重复宣称其为盲测。
5. 旧实验已经使用过全部1390帧，因此该`final_test`只是从2026-09-22开始的前瞻性冻结集，并非历史上从未接触的真正盲测集。论文中必须披露这一点。

## 5. 已知限制

- 前390帧缺少逐采集文件夹来源，不能用于跨采集组测试。
- 19帧double-target中18帧集中在同一原始采集文件夹。该文件夹保留在训练集，最终确认集中只有1帧double-target，因此不能从本划分得出可靠的double-target跨组结论。
- 当前所有数据均曾参与历史实验。若条件允许，仍应补采一个完全未用于开发的新批次，作为真正盲测集。
- 当前划分隔离的是原始录制文件，不自动保证目标实体、背景场景或实验日期完全独立；后续获得更完整元数据时应新增更严格版本，不覆盖v1。

## 6. 生成与校验

首次生成：

```bash
python scripts/prepare_private_paper_split.py prepare
```

之后只执行只读校验：

```bash
python scripts/prepare_private_paper_split.py verify
```

输出目录：`data/new_data/merged/paper_split_v1/`。

核心文件：

- `frame_acquisition_metadata.csv`：逐帧来源、类别、当前标签摘要和固定集合；
- `train_indices.npy/.txt`；
- `dev_indices.npy/.txt`；
- `final_test_indices.npy/.txt`；
- `verified_train_indices.npy/.txt`；
- `split_manifest.json`：来源哈希、固定规则、规模和限制；
- `frozen_output_sha256.json`：冻结输出的完整性哈希。
